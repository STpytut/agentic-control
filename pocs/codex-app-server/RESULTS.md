## Discovered integration constraints

### 1. Wait for `turn/started` before steering

The first run sent `turn/steer` immediately after the successful `turn/start`
response. The server returned:

```text
no active turn to steer
```

The turn ID is therefore not sufficient evidence that the turn is already
steerable. The adapter must wait for the matching `turn/started` notification
and then send `turn/steer` with the required `expectedTurnId` precondition.

### 2. The protocol is version-sensitive

App-server is experimental. Production code must pin a supported CLI range,
generate/store schemas for that version, and block write-capable startup after
an unknown upgrade until a smoke test passes.

### 3. Server requests need a strict dispatcher

Approval is a server-to-client request with its own `id`; it is not a regular
notification. The client must respond to that exact ID. The PoC only accepts
known command/file approval methods and rejects unknown server requests with
JSON-RPC error `-32601`.

### 4. Test auto-approval is not a production policy

The PoC automatically accepted one intentionally isolated approval request.
The product adapter must persist the request, surface it to the authorized user,
validate the response against the current thread/turn/item, and fail closed on
timeout, disconnect, stale IDs, or unsupported decision types.

### 5. Keep the transport local

The validated architecture is app-server stdio under the runtime supervisor.
There is no reason to expose its experimental WebSocket transport publicly.
Remote product clients should connect to the platform API, not directly to
app-server.

## Decision

`codex app-server` is approved with limitations as the Codex interactive
adapter interface for the MVP vertical slice. It provides the required
bidirectional control, structured events, active-turn steering, interrupt, and
approval exchange on the target VPS.

Because the interface is experimental, the adapter must be version-pinned and
schema-tested. Stable `codex exec --json` remains the simpler fallback for
non-interactive batch jobs.
