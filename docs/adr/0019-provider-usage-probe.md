# ADR-0019: Проба лимитов провайдера от имени пользователя рантайма

- Status: Accepted (2026-09-29, the owner: OpenCode Go only)
- Date: 2026-09-29

## Context

Владелец хочет видеть в панели лимиты подписок и расход в реальном времени
(этап 12, после W1–W8). Что можно узнать, не нарушая правила «учётные данные не
покидают пользователя рантайма» ([ADR-0012](0012-runtime-provisioning-supply-chain.md)),
выяснено в [REASONING_AND_LIMITS_RESEARCH.md](../REASONING_AND_LIMITS_RESEARCH.md):

| Аккаунт | Лимиты | Откуда | Нужен ключ вне рантайма? |
| --- | --- | --- | --- |
| ChatGPT (Codex) | окна 5 ч и неделя, кредиты, план | `account/rateLimits/read` и события `account/rateLimits/updated` app-server'а | нет — отвечает сам рантайм |
| Claude (подписка) | окна 5 ч и 7 дней | `rate_limit_event` в stream-json, только во время хода | нет |
| OpenCode Go | окна rolling / неделя / месяц | `GET https://opencode.ai/zen/go/v1/usage` | **да** — ключ из `auth.json` |
| OpenRouter | лимитов нет; есть баланс аккаунта — **не трогаем** (владелец) | — | — |
| OpenCode Zen | бесплатный, лимитов нет | — | — |

OpenCode не отдаёт лимиты ни в CLI, ни через свой сервер. Для OpenCode Go
остаётся одно: чтобы запрос сделал **пользователь рантайма**
(`opencode-worker`), своим ключом, а платформа получила только числа.

Сейчас супервизор уже делает похожее и нигде не видит байтов учётных данных: логин
копируется во временный каталог квалификации через `runuser … cp`, наличие логина
проверяется через `test -s` по коду выхода.

## Decision

### 1. Фиксированная проба в релизе

`services/runtime-supervisor/provider-usage.mjs` — небольшая программа,
которая лежит в дереве релиза (root-owned, входит в подписанный артефакт) и
запускается супервизором так же, как рантайм:
`runuser -u opencode-worker -- /usr/bin/env -i HOME=… PATH=… /opt/node/bin/node <проба> <провайдер>`.

- **Аргументов нет**: проба знает один провайдер, `opencode-go`, и один адрес —
  константу в коде. Никаких URL, путей и заголовков из запроса.
- **Ключ читает только проба**, из `~/.local/share/opencode/auth.json` пользователя
  рантайма, по фиксированному имени записи. Супервизор и воркеры ключ не видят.
- **Сеть**: только HTTPS на `opencode.ai`, таймаут 10 с, ответ не больше 64 КБ,
  без редиректов на другие хосты.
- **Вывод — одна строка JSON по закрытой схеме**: только числа, даты и слова из
  перечисления (проценты окон, время сброса, лимит, расход, признак free tier,
  класс ошибки `unauthorized | unavailable | malformed | timeout`). Тело ответа
  провайдера, тексты ошибок и сам ключ не печатаются никогда. stderr пробы
  супервизор отбрасывает.

### 2. Супервизор проверяет вывод, а не доверяет ему

Супервизор разбирает stdout по той же схеме и отбрасывает всё, что в неё не
укладывается: лишние поля, строки вне перечислений, числа вне диапазонов, вывод
длиннее 4 КБ. В базу (`provider_usage_readings`) попадает только прошедшее
проверку. Если проба изменится или сломается, в худшем случае получится «лимит
неизвестен», а не утечка.

### 3. Когда запускается

По запросу панели не чаще раза в 5 минут на подключение, и после завершения
задачи на этом подключении. Проба — это не запуск модели: учёт памяти K3 её не
касается, но число одновременных проб ограничено одной.

### 4. Что показываем

Для OpenCode Go — окна из пробы с временем чтения, и **по каждой модели** сколько
запросов сделали наши запуски в текущем окне рядом с оценкой, опубликованной на
opencode.ai/go («примерно столько запросов за 5 часов»). Эта таблица оценок лежит
в релизе с источником и датой, как таблица уровней рассуждения Claude, и
подписана в панели как оценка. Для OpenRouter — только расход (токены и деньги по
нашим запускам); лимитов у него нет, а баланс аккаунта мы не читаем. Для OpenCode
Zen — «бесплатно, без лимитов». Для ChatGPT и
Claude — лимиты из самого рантайма (без пробы). Расход в реальном времени — из
токенов и стоимости, которые рантаймы уже присылают в потоке. Стоимость OpenCode
подписывается как оценка по прайсу, а не счёт провайдера.

## Threat model

| Угроза | Что мешает |
| --- | --- |
| ключ уходит в вывод пробы | схема вывода — только числа и перечисления; супервизор отбрасывает остальное |
| ключ уходит в журнал | stderr пробы не читается; тела ответов не печатаются |
| подмена пробы | файл в дереве релиза, root-owned, в подписанном артефакте; пользователь рантайма его не изменит |
| запрос на чужой адрес (SSRF) | один адрес — константа; аргументов нет |
| проба как канал для другого кода | запускается только она, фиксированным путём, `env -i`, без stdin |
| недокументированный эндпоинт Go меняется | ответ, не прошедший разбор, даёт `malformed`, а панель пишет «неизвестно» |

## Alternatives considered

- **Супервизор читает ключ сам** — отклонено: правило ADR-0012 перестаёт быть
  правилом, если у него есть «удобное» исключение.
- **Просить OpenCode отдавать лимиты** — нет в 1.18.32; можно предложить upstream,
  но ждать нельзя.
- **Показывать только расход** — остаётся запасным вариантом, если ADR не принят.

## Consequences

- В релизе появляется первый код, который выполняется от имени пользователя
  рантайма и не является самим рантаймом. Его границы задаёт этот ADR; добавить
  провайдера или адрес (например, OpenRouter) — только поправкой к нему.
- Эндпоинт OpenCode Go недокументирован и может измениться — это видно в панели
  как «неизвестно», а не как ошибка задачи.
- `doctor` проверяет, что проба на месте, её дайджест совпадает с манифестом
  релиза, и она root-owned.
