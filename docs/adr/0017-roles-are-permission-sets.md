# ADR-0017: Роль — это набор прав из закрытого словаря

- Status: Accepted (owner, 2026-09-26)
- Date: 2026-09-26
- Stage: 11.3, спринт B (пакеты R2–R4, миграции `0079`–`0081`)
- Решения владельца: B1–B4 в [STAGE_11_SPRINT_B_PLAN.md](../STAGE_11_SPRINT_B_PLAN.md) §3
- Уточняет: [ADR-0009](0009-configurable-agent-roster.md) (roster назначений),
  [ADR-0006](0006-codex-publishing-authority.md) (публикация — только после одобрения)

## Context

Две фиксированные системы слов связаны друг с другом:

- `agents.role ∈ {architect, reviewer, implementer}`;
- `project_agent_assignments.assignment_role ∈ {orchestrator, executor}`.

Решения рабочего процесса читают их как полномочия:

- сообщение маршрутизируется `orchestrator`;
- реализация достаётся `executor`;
- несколько функций проверяют `a.role IN ('architect','reviewer')`.

В 11.2 из этих решений убрали производителя (`runtime_plays()`, 0074), но сами роли остались двумя словами, и знакомое имя по-прежнему даёт право. Оператор не может описать команду, отличную от «один оркестратор, N исполнителей», а база не может сказать, почему назначение допустимо.

## Decision

### 1. Права — закрытый словарь машинных ключей

| Право | Что разрешает |
| --- | --- |
| `conversation.hold` | вести разговор задачи: получать сообщения, делегировать, просить ревизию |
| `implementation.execute` | получать handoff и менять workspace под fencing-токеном |
| `review.perform` | получать свидетельство и выносить вердикт, привязанный к его дайджесту |
| `publish.request` | *просить* подготовить публикацию; саму публикацию не выполняет |
| `completion.required` | реализация не завершена без свидетельства, в котором прошли все платформенные проверки |

Словарь расширяется только миграцией. Имя и описание роли — представление: решения их не читают.

### 2. Роль — определение с набором прав; назначение ссылается на определение

- `role_definitions` принадлежит владельцу и версионируется. Встроенные определения помечены и не редактируются.
- `role_permissions` — это права определения.
- `project_agent_assignments.role_definition_id` заменяет `assignment_role`.
- Задача при создании снимает набор прав своих назначений. Правка роли меняет новые задачи и никогда не меняет задачи в полёте, так же как снимок модели (0028).

### 3. Встроенные определения повторяют сегодняшнее поведение (B1)

| Определение | Права |
| --- | --- |
| Orchestrator | `conversation.hold`, `review.perform`, `publish.request` |
| Executor | `implementation.execute`, `completion.required` |

Backfill ставит каждому назначению встроенное определение по его `assignment_role`. Проверка эквивалентности сравнивает решения и события до и после миграции, а не число строк. Схема допускает собственные определения, но в спринте B создаются только встроенные; редактор ролей появится в 11.5.

### 4. Кратность и недопустимые сочетания (B2)

- **Ведущий разговор.** В проекте ровно одно включённое назначение по умолчанию с `conversation.hold`. Второе отвергает триггер.
- **Исполнители.** `implementation.execute` — одно или несколько назначений, в порядке приоритета, который уже есть у списка исполнителей.
- **Ревью.** В спринте B `review.perform` есть только у назначения с `conversation.hold`: ревьюирует тот, кто ведёт разговор. Отдельный ревьюер появится в 11.5.
- **Недопустимые сочетания:**
  - `implementation.execute` вместе с `conversation.hold` в одном определении: пишущий и ведущий разговор — разные прогоны с разными гарантиями, read-only против записи;
  - `review.perform` без `conversation.hold`, пока отдельный ревьюер не введён;
  - `completion.required` без `implementation.execute`.

### 5. Каждое право требует возможностей runtime (B4)

| Право | Возможности драйвера |
| --- | --- |
| `conversation.hold` | `run.read_only`, `tools.platform` |
| `review.perform` | `run.read_only`, `tools.platform` и получение свидетельства |
| `implementation.execute` | `run.workspace_write` и инструменты терминального отчёта |
| `publish.request`, `completion.required` | нет: это контракт, а не свойство runtime |

Соответствие «право → возможность» лежит в зеркале реестра (0074). Назначение, runtime которого не имеет нужной возможности, отвергает база — при записи назначения и повторно при dispatch. Интерфейс не является границей безопасности.

### 6. Что такое завершённая реализация (B3)

`completion.required` выполняется, когда у реализации есть записанное свидетельство, в нём прошли **все** платформенные проверки, включая `worktree_committed`, и есть проходящий вердикт. Ревью не может пройти дерево, которого нет ни в одном коммите. Исполнителю сказано коммитить свои файлы (B0).

### 7. Публикация остаётся за одобрением оператора при любых ролях

`publish.request` даёт агенту только возможность *попросить*. Подготовка публикации, push и PR происходят после одобрения оператора и только по дайджесту одобренного свидетельства ([ADR-0015](0015-review-evidence-and-publish-boundary.md)). Никакой набор прав этого не отменяет: в словаре нет права «опубликовать».

### 8. Каждое изменение принадлежит владельцу, ограничено версией и попадает в аудит

- Функции, меняющие определения и назначения, проверяют владельца и ожидаемую версию и пишут `write_audit_event`.
- Список функций `infra_web` и тесты привязки актора обновляются на всю достижимую поверхность.

## Consequences

- Решения читают права, а не слова (0080). Статический тест не пускает `assignment_role`, `'architect'`, `'reviewer'` и `'implementer'` в функции за пределами backfill.
- Переход идёт в два шага, expand и contract (0079, затем 0081), как с именами заданий (0073/0077).
- 11.5 получает данные и функции для редактора команды без новой схемы.

## Rejected alternatives

- **Расширить `assignment_role` новыми словами.** Право по-прежнему выводилось бы из имени, а сочетания — неявно из кода.
- **Хранить права в JSON у назначения.** Базе нечем проверить сочетания и возможности, а снимку задачи — сослаться на версию определения.
- **Отдельный ревьюер сразу.** Сейчас ревью — это ход того же разговора с его сессией. Отдельный ревьюер требует второй сессии и своего свидетельства доставки; это задача 11.5, а не спринта B.

## Amendment (2026-09-26, R4)

`assignment_role` is not dropped. It stays as the definition's *projection*: the trigger of 0079 is its only writer, derived from whether the definition holds `conversation.hold`. The one-default-orchestrator index and the assignment's unique key are built on it, and a unique index cannot reach into another table's rows. Nothing decides on it (`db/tests/0051`). `agents.role` is dropped from every decision and constraint and stays as history.
